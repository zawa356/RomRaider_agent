# 01. 要求・制約・前提

出典: `docs/handoff/` の引継ぎ資料（2026-10-10 ChatGPT版初版、2026-10-12 Claude版更新）と、2026-10-12 のClaude Coworkでの会話。

## 1. 出発点 [ユーザー発言]

- RomRaider Loggerの設定、特に**取得ログ項目（パラメーター）の手動変更が煩雑**。
- ChatGPTやClaudeからMCP経由で設定を読み書きしたい。
- 単なる設定編集ではなく、最終目標は**RomRaider全体の操作**（ログ取得の開始・停止、状態照会、CSV解析を含む）。会話上「B案」として指定された。

## 2. 自動計測の最終目標 [ユーザー発言]

- 運転中にPCを触るのは難しいので、あらかじめ許可した範囲でシステムがログを区切り、解析し、**次に取得するパラメーターをLLMが動的に判断**して情報を集めていく。
- 例: 基本項目 → 点火・ノック関連 → 燃調関連、と調査目的に応じて切り替える（例示であり、現車への適用可否は要検証）。
- CSVをローカルで構造化し、SQLで検索・比較したい（ユーザーの入力に「CVS」表記もあったが文脈上CSV）。
- 走行中の**LLMによるオンライン判断**を最終的に望む（引継ぎ資料では「方式1」）。
- スマホを車載ホルダーに固定して音声で会話し、状況確認、計測方針の変更、気付いた症状へのタイムスタンプ付きマーカー登録をしたい。

## 3. 2026-10-12 に追加された要求 [ユーザー発言]

- ローカルCSVだけではリアルタイム分析ができない可能性がある。**RomRaiderから直接、SQLサーバーなどにデータを転送**し、**音声モードのスマホからHTTPのMCPとして解析を呼び出せる構造**にしたい。
- 「ログを取った後」だけでなく「ログを取りながら」別の場所へ転送できるかを検証してほしい。
- サーバーは「VPC」ではなく **VPS（レンタルサーバー）**。OSやWebサーバー（Apache／Nginx）は未決定で、構成の提案がほしい。**自宅PCにVPNを張ってSQLサーバーを立てる**ことも可能。
- 作成したエージェントをGitHubリポジトリ `zawa356/RomRaider_agent`（private）で管理したい。
- README・設計方針・履歴は**主にAIが読む**ので、要約より**情報量を重視**して書いてほしい。

## 4. 制約 [ユーザー発言]

- LLM APIの**従量課金は極力避けたい**。
- ChatGPT Work／Claude Cowork／Codex／Claude Code は**サブスクの使用量が厳しい**ので、常時稼働の主方式にはしづらい。
- 通常のチャット・拡張機能・音声モードで済む方法を検討したい。
- 通信回線は**使える前提でよい**。
- ChatGPTデスクトップ＋Workモードで**ローカルstdioのMCPが動くことは確認済み**（ユーザーが確認）。ただし使用量の都合で常用には消極的。

## 5. 安全・権限に関する方針（引継ぎ資料 §7 より）

- ロガーの取得項目切替は、既知の安全条件と停車条件を満たす場合に限定する方向。走行中の画面操作を要求しない。
- 車両の運転に影響する制御、ECUのROM書換、FW更新は除外。
- LLMからの計画変更は、取得項目のホワイトリスト、Logger定義・ECU適合、件数・サンプリング制約、競合防止、承認範囲と照合する。
- 一時停止・通信断・MCP不能でも収集済みデータは保持する。失敗した計画は直前の検証済み計画に戻せるようにする。
- DBの読み取りは専用の読み取り権限で行い、任意のSQLやOSコマンドをMCPから無制限に実行させない。
- 認証済みHTTPSを使い、DBをインターネットに直接公開しない。
