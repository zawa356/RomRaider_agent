# Cooperative lane ownership v1 (isolated, default disabled)

Logical key is the exact canonical device UUID, vehicle UUID and payload session (bounded UTF-8); physical source UUIDs do not enter the key. Multiple explicitly admitted sources share one ingestion lane. Writer publication, sender transport and Server ACK are separate responsibilities.

All participating processes must use the same existing private canonical local ownership directory. One persistent RLLO1 file per key is held with an exclusive OS FileLock throughout import and output commit. Never unlink or replace a lock file. Unknown versions, changed identity/owner/generation, closed lock and malformed evidence refuse; there is no timed lease expiry or PID-based takeover. PID reuse has no ownership significance. A new owner obtains the kernel lock after process exit and advances the persisted generation. Generation is an integrity/diagnostic token, not a distributed database fence. A retained kernel lock prevents cooperative generation change; no forced revocation exists.

Lock order: legacy DB .worker.lock compatibility guard, lane, publication boundary, SQLite transaction. Separate SQLite DBs never form one transaction. The RLC2 candidate holds the configured legacy Worker lock from before input snapshot to after commit, including when the new common lane is not enabled. This excludes Workers using that exact DB lock only; direct old importers, other DBs, unlisted old binaries and noncooperative writers are not safe coexistence. Legacy lock files are not deleted. Legacy compatibility serializes different sessions sharing one old DB; different lanes can run concurrently absent that compatibility bottleneck.

Opt-in common ownership is for synthetic isolated tests. Old offline API remains externally quiescent; new common ownership does not enable live logging, migration, deletion, sender or formal ACK. Check owner before writes and immediately before commit, while retaining lock to commit completion. Lease timeout alone never authorizes takeover; filesystem/network/distributed locks and administrator path mutation are outside the guarantee. Windows directory durability UNKNOWN.

A historical old Worker cannot recognize a new mode: unknown command flags already fail closed, and RLI2 output cannot be a v1 spool. Do not claim that a new environment flag makes unmodified old binaries cooperative. Existing claim/cursor/record IDs and ACK state stay unchanged.

Java Windows fileKey can be unavailable: retain OS lock and validate sampled creation time plus exact handle-bound owner evidence; POSIX additionally compares fileKey. This is cooperative path integrity, not a native identity/administrator-attack guarantee. Windows process termination can precede kernel lock release; BUSY remains refusal until an explicit retry actually acquires it. No elapsed-time takeover.

## Product opt-in integration
`DurableSpool(file, laneRoot)` and `ProductBridgeWorker` environment `ROMLOGGER_SYNTHETIC_LANE_ROOT` explicitly enable isolated ownership. Default constructor/environment absence keep it disabled. Incremental TSV/Journal importers acquire a scope per payload session; scanners use these importers. Spool requires that scope at claim, profile/record append and cursor writes, and verifies immediately before ingestion commits. Transport and ACK commits are independent. A scope closes on its acquiring thread only.

`Rlc2IntegrationStore.ingestCooperative(enable, externallyQuiescent, root, payloadSession, ...)` holds compatibility guard then common lane before snapshot; projected payload must match the lane. It still explicitly requires external quiescence. Separate-session locking alone does not prevent a noncooperative Writer update.
