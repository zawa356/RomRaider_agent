# Phase 2.1-D1：旧TSV継続取り込みと永続カーソル

## 背景と実装

Phase 2.1-C1の`LegacyTsvBridge.importFile`は明示実行時に既存TSVの**先頭から全行を読み直していた**。同じレコードIDの重複除外は機能するが、長時間走行中に繰り返すとログ全体のサイズに比例した読み込みコストがかかる。

今回、独立した`IncrementalTsvBridge`を追加し、`ProductBridgeOnce`がこれを使用するよう変更した。既存の`Stream.java`、`Agent.java`、RomRaider Loggerコールバック、旧送信・操作系は**無変更**。

```text
既存 rr_*.tsv（読み取り専用） ── 完結済みLF行のみ
      ↓ RandomAccessFile.seek(保存済みoffset)
増分取り込み／メタデータ復元（最大256行／CLI 1回）
      ↓
SQLite v1_profiles / v1_records（各レコードを先に永続commit）
      ↓ 成功後にのみ
SQLite v1_import_cursors（offset＋行番号＋メタデータ状態＋ファイル識別・hash）
      ↓
ProductSender.pumpOnce()（従来どおり最大1 HTTP要求）
```

## 保全ルール

- DB保存の完了**後**にカーソルを更新する。クラッシュにより「レコードのみ保存、カーソルは旧位置」の状態になったら同じ行を再処理し、**不変record IDとSQLite一意制約で重複させない**。
- チェックポイントは原本ファイルのcanonical path、device ID、vehicle ID、OSが返すfileKey、取り込み済み位置、行番号、元ファイル先頭のSHA-256、カーソル直前の末尾128バイトSHA-256、セグメント別パラメーター定義と状態を保存。古い状態のCASによる後退更新を拒否する
- `LF`で終わっていない行は読みかけとして残し、カーソルを進めない。形式不正・NaN・必要な定義欠落時も**カーソルを進めず、元行を無視しない**。
- 同一ファイルの短縮、OS fileKey変更、取り込み済み先頭／末尾アンカーが改変された場合は、**自動リセット・データ消去をせず異常終了**する。
- メタデータのスナップショットがカーソルと同時に確定するので、再起動後に過去のM行を再読込して状態を復元する必要がない。
- 1回のCLI取り込みは最大256の完結行まで。大量残データは複数回の明示実行で処理する。バックグラウンド常駐プロセスではない。

## 制約と注意事項

- ファイル識別はOSのfileKeyに依存する。WindowsなどでfileKeyが得られない場合には先頭・境界ハッシュで補助検査するが、**取り込み済みファイル全体の改変を完全検知できるわけではない**。再利用された同名ファイルの取り違え防止は実車で追加検証が必要。
- 既存PoCのbounded queue overflow、TSV writer書込み失敗、14日削除、ローテーション、キューへ届く前の計測欠落を防ぐものではない。
- **カーソルに記録されるのはServer ACKではなく、ローカルSQLiteへの取り込み完了位置**。Server送信と受領ACKは従来どおり`v1_records`側で管理する。
- 途中でプロファイル定義や値が矛盾した場合は記録・通知が必要。単体ツールでは例外停止するが、継続監視／不正レコード隔離／ユーザー向け異常通知は後続Phase。
- 1完結行ごとにSQLiteトランザクションを実行するため、長時間・高頻度Loggerでのスループット・容量評価は未実施。バッチ化はデータ保全試験後。
- TSV内容を読むときに同時に上流がファイルを書き換える等の異常状態では、通常の追記専用書込みを前提とする。部分書込み・物理停電耐性の実車検証は未実施。
- Java8`--release 8`コンパイル＋Windows/Linux実SQLite試験は、**Zulu8 32-bit/X270実動作と同一ではない**。
- Server側にpinされているAgent E2EのJavaコードは古いコミットで、今回の増分カーソルはまだ含まれない。Phase 2.1-D2で再pin・実Server E2Eを実施する。

## 合成CI試験

`IncrementalTsvBridgeTest`（Windows/Linuxマトリクス）では以下を試す。

- 行数制限・EOF後の再呼出・追加されたサンプルだけを読み込む動作
- 永続metadata定義の再起動復元／元TSV全行読み直し不要
- **行保存後／カーソルcommit前**に例外停止する障害注入、再起動後の同一record ID再処理
- LFなし途中行が完成するまで保留
- 無効データでカーソルを進めず保持し、未処理末尾の修復後に再開
- TSVの既処理先頭部改変・truncateを拒否
- 旧`LegacyTsvBridge`との同一レコードID互換を維持

履歴と実際のCI結果は[Phase実装進捗](product_v1_implementation_progress.md)を参照。
